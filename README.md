# 野球シミュレーションゲーム v0.1

架空2球団の試合を1球ずつ自動計算し、スコア・個人成績を表示、ブラウザへ保存・再表示できます。採用した試作規則の範囲で、引き継ぎメモのMVP-01～08を検証しています。数式と係数は未校正で、最終仕様・公式野球規則の完全実装ではありません。

## 起動と遊び方

Windows / PowerShell、Node.js **24.15.0**、npm **11.12.1**で確認しています。

```powershell
npm.cmd ci
npm.cmd run dev
```

表示されたURL（通常 `http://127.0.0.1:5173/`）を開きます。Ctrl+Cで開発サーバーを停止できます。

1. 既定は「併殺・犠飛対応試作 v7」です。「試合モデル」で従来v1〜v6も選べます。設定を変えたら「新しい試合を準備」で適用します。「1試合を自動進行」で試合終了まで進めます。「一時停止」は処理中の最大25イベントが終わると止まります。
2. スコア、イニング別得点、打者・投手成績を確認します。狭い画面では表の中を横スクロールできます。
3. 「試合結果を保存」を押します。ページを再読み込みし、「保存した試合を読み込む」で同じ結果を表示できます。
4. seedを変え、「新しい試合を準備」で次の試合を始めます。未保存の試合は置き換わります。
5. 2回以上保存すると、「前の保存を読み込む」で最新保存の直前の結果を表示できます。

同じseed・固定データ・モデル版・開始時の設定なら同じ記録になります。同梱設定で初期seed `20260923` のv7は**星原7対青凪9、403球・103打席、併殺2件**です。犠飛の確認にはseed `387276917`（星原3対青凪0、299球）を使えます。v6では**星原2対青凪3、9回（裏なし）・326球・87打席**です。v5の6対2・362球、v4の0対7・334球、v3の2対0・284球、v2の9対1・235球、v1の12回0対0・234球も維持し、既存保存は記録された版で復元します。

v7では併殺と犠牲フライを追加しました。投球・打球・走塁の既存係数はv6から変更していません。設定ファイルは [config/match.ts](config/match.ts)、編集方法・単位・新プレーの仮定は [設定の説明](config/README.md) を参照してください。係数の校正は後工程に回しています。

「1イベント進める」は投球のほか、攻守交代や投手交代も1件として進めます。以前の「1球の検証」画面も残してあり、こちらは四球・三振・フェア接触の境界で停止する独立した実験です。

## 対応範囲と仮定

- 架空24選手：各球団は打順9人（DHを含む）と投手3人。球種はストレート・スライダー・フォーク。
- 9回制、同点なら最大12回、裏の省略・サヨナラ・引き分け。先発90球、次の投手50球を目安に打席間で継投します。
- 四死球、三振、単打、二塁打、三塁打、本塁打、打球アウト。能力から打球速度・角度、守備到達時間を計算します。
- 安打時の既存走者は獲得塁数に加え、v2以降では走力・返球時間に応じて最大1塁追加進塁します。v7の犠飛以外のアウトでは進みません。責任投手を走者ごとに保持します。
- v7の併殺：無死・一死で一塁走者がいるP/3B/SS/2Bのゴロ捕球から、二塁フォースと一塁アウトが間に合う場合。打席結果は打球アウトとし、2件のアウトと併殺打を記録します。
- v7の犠飛：無死・一死の外野フライ捕球後、三塁走者が安全余裕を持って本塁へ到達できる場合。打席1・打数0・犠飛1・打点1、走者の責任投手へ失点を付けます。両プレーともその他の走者は元の塁に留めます。
- 失策・盗塁・犠打・振り逃げ・暴投・捕逸・野手交代・二刀流運用・投手の勝敗／セーブは未対応です。疲労・天候・成長も未適用です。併殺崩れ・野選・走塁死・飛球併殺・全守備成績も未対応です。
- 計算上限は1打席100球・1試合10000球。上限到達は異常停止として扱い、正常な結果として保存しません。

打率は安打÷打数、防御率は27×自責点÷投球アウトから表示します。投球回の小数部分はアウト数です（5.2＝5回2/3）。未観測の率は「-」、投球アウト0で自責点が正なら「上限」と表示し、非有限数は保存しません。

モデルの仮定は [設定の説明](config/README.md) とローカルの [試作モデル](Docs/knowledge/prototype-model.md) に記録しています。新モデルの計算は `pitch-configured.ts`、`batted-ball-configured.ts`、`in-play.ts`、モデル選択は `src/game/model-registry.ts` です。旧v1〜v6の定義と計算は保持します。**ゲーム版はv0.1**、v7は試作アルゴリズムの版です。

## 保存

IndexedDB＋DexieをStorageAdapter経由で使用します。保存形式はv1の **v01-completed-game-1**、v2の **v01-completed-game-2**、v3の **v01-completed-game-3**、v4の **v01-completed-game-4**、v5の **v01-completed-game-5**、v6の **v01-completed-game-6**、v7の **v01-completed-game-7** に対応し、対象は同梱の固定名簿で正常終了した1試合です。

v7は開始時の設定全体も保存します。設定ファイルを変更しても、保存済みの試合は当時の設定で復元・再実行します。設定内容は定義ブロックのハッシュで識別し、アルゴリズム版と区別します。

4物理ストア（local_worlds、save_slots、save_snapshots、save_blocks）に、モデル定義・名簿・全イベント・最終状態・成績・完全な乱数状態を保存します。版・ハッシュ・再計算による整合確認を通してから復元します。未知の版や破損を検出した場合はエラーにし、表示中の試合を維持します。保存中の失敗では4ストアをまとめて取り消し、以前の保存を残します。

手動保存1枠と直前の保存に対応します。試合中保存・自動保存・外部ファイルへの書き出し・クラウド同期・正式な全世界セーブとの互換性はありません。履歴の自動削除は未実装で、保存を重ねると容量を使います。保存先は同じブラウザ・同じURLのオリジンです。開発用5173番とプレビュー用4173番は別の保存先になり、サイトデータを削除すると保存も消えます。

## 検証

```powershell
npm.cmd run check
npm.cmd run test:ui
npm.cmd run format:check
```

`check` は型検査・69件のNode試験・ビルドを行います。試合100条件、走者と得点の境界、継投、サヨナラ、結果確定の二重適用防止、保存失敗・競合・破損拒否を含みます。三塁打は固定名簿の100条件での観測とは分け、極端な能力の分岐試験で確認しています。既存の1球試験は2,000乱数条件を含みます。変更前に凍結したv1〜v6セーブと計24条件の全記録ハッシュで互換性を検証し、実ブラウザでも旧v1/v2/v3/v4/v5/v6保存→v7保存→前保存の復元を確認します。

新プレーの固定入力試験と80条件の生成試験で、第三アウトでの得点抑止・サヨナラ・責任投手・打席内訳を検査します。設定の不正値拒否、既定値変更後の保存復元、既定設定での旧v6投球・打球一致も確認します。

`test:ui` はビルド済みのdistを4173番で配信し、インストール済みMicrosoft Edgeで12件を実行します。1280px・390px幅で、自動進行→保存→ページ再読み込み→復元→前保存→同条件再現と、以前の1球画面を確認します。Android実機や他ブラウザでの検証は未実施です。

| コマンド                        | 用途                              |
| ------------------------------- | --------------------------------- |
| `npm.cmd run game -- 20260923`  | 画面を使わず1試合の結果をJSON表示 |
| `npm.cmd run pitch -- 20260923` | 以前の1球試作の結果をJSON表示     |
| `npm.cmd run build`             | 型検査後、静的配信用distを生成    |
| `npm.cmd run preview`           | ビルド済み画面をローカル確認      |
| `npm.cmd run format`            | コードと設定を整形                |
| `npm.cmd run format:check`      | 書式を変更せず検査                |

## モデルの比較

```powershell
npm.cmd run analyze:models -- 200 1
npm.cmd run analyze:models -- 300 4001
npm.cmd run game -- 20260923 game-prototype-v1
npm.cmd run game -- 20260923 game-prototype-v2
npm.cmd run game -- 20260923 game-prototype-v3
npm.cmd run game -- 20260923 game-prototype-v4
npm.cmd run game -- 20260923 game-prototype-v5
npm.cmd run game -- 20260923 game-prototype-v6
```

`analyze:models` の引数は試合数と開始番号です。seedは `imul(i,2654435761) >>> 0` で生成し、7モデルの平均得点、打率、球数／打席、四死球率、三振率と見逃し／ゾーン内外の空振り内訳、2ストライク後のゾーン別スイング・接触・ファウル、カウント別スイング、打球種類別アウト率等をJSON表示します。ストライク数別のフェア打球数・平均速度・安打・塁打、得点走者の出塁理由（scoredByReach）と得点が発生したプレー（runsByPlay）も別々に集計し、各得点内訳の合計をスコアと照合します。カウント別のゾーン内球数（pitchCounts.inside）、四球の決着ストライク数（walkCounts）、決着直前が満塁だった打席・四死球・押し出し（basesLoaded）も確認できます。ファイルへ残す場合は `> .tmp/model-report.json` を付けられます（事前に出力先フォルダを作成してください）。詳しい式と調査結果はローカルの[試作モデル](Docs/knowledge/prototype-model.md)に記録しています。

## 構成と開発方針

| 場所                 | 役割                                                     |
| -------------------- | -------------------------------------------------------- |
| `config/`            | 新規v7試合の係数と編集方法                               |
| `src/engine/`        | 既存の1球計算、乱数、境界検査                            |
| `src/game/`          | 固定名簿、打球・守備・走者、試合進行、成績、指示処理     |
| `src/game-worker.ts` | 試合状態を所有し、指示を直列に処理                       |
| `src/storage/`       | 保存の入口、直列化と検査、Dexie実装                      |
| `src/ui/`            | Reactの画面、表示用コピー、入力                          |
| `tests/`・`e2e/`     | 計算・保存・実ブラウザの検証                             |
| `Docs/knowledge/`    | quiz_app方式の現状・判断・知見・作業履歴（ローカル専用） |

計算はReact・DOM・DBから独立し、Workerだけが試合の正本を更新します。表示、一時停止、保存操作は試合用乱数を進めません。率の表示からカウンタを書き戻しません。試合終了で日付やシーズンを進める処理もありません。

型はデータ設計書v1.0のID・単位・記録境界を参考にした**v0.1試作向けの部分実装**です。正式な全プロフィール・全能力・全世界モデルを実装したものではなく、省略項目を0や空オブジェクトで補いません。
