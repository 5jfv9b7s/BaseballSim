## Cloudflareのテスト公開準備

現在の開発版から、通常distを保ったテスト用配信物を作れます。`npm.cmd run cloudflare:prepare` → `npm.cmd run cloudflare:dry-run` → `npm.cmd run test:cloudflare:ui`で確認します。ローカルで触る場合は`npm.cmd run cloudflare:dev`です。[導入済みの設定・実行手順・検証結果](CLOUDFLARE-TEST.md)を参照してください。実際のCloudflareログイン・公開・URL取得は後の工程です。セーブはURLごとに分かれ、移動には`.bssave`を使います。

## 起動と遊び方

Windows / PowerShell、Node.js **24.15.0**、npm **11.12.1**で確認しています。

```powershell
npm.cmd ci
npm.cmd run dev
```

表示されたURL（通常 `http://127.0.0.1:5173/`）を開きます。Ctrl+Cで開発サーバーを停止できます。

本画面では「今日の試合へ」→「1日を自動進行」で翌日へ進みます。「システム」→「セーブ・再開」で保存を読み込みます。新しい年間プレイは「システム」→「新規プレイ」で準備します。詳しくは[本画面の操作](MAIN-SCREEN-IMPLEMENTATION.md)を参照してください。

以下は「シミュレーション開発ツール」または `/?tools=1` で開く、独立した1試合検証の手順です。

1. 既定は「捕球失策対応試作 v10」です。「試合モデル」で従来v1〜v9も選べます。設定を変えたら「新しい試合を準備」で適用します。「1試合を自動進行」で試合終了まで進めます。「一時停止」は処理中の最大25イベントが終わると止まります。
2. スコア、イニング別得点、打者・投手・守備成績を確認します。狭い画面では表の中を横スクロールできます。
3. 「試合結果を保存」を押します。ページを再読み込みし、「保存した試合を読み込む」で同じ結果を表示できます。
4. seedを変え、「新しい試合を準備」で次の試合を始めます。未保存の試合は置き換わります。
5. 2回以上保存すると、「前の保存を読み込む」で最新保存の直前の結果を表示できます。

同じseed・固定データ・モデル版・開始時の設定なら同じ記録になります。同梱設定で初期seed `20260923` のv10は**星原2対青凪3、310球・81打席**です。

捕球失策の確認には、v10でseed **`3668339987`** を使ってください。**星原1対青凪4、275球・75打席**となり、星原のチーム失策3・チーム自責点3、先発の川瀬陸は失点4・自責点3になります。「試合結果を保存」→再読み込み→「保存した試合を読み込む」で同じ成績を確認できます。

旧v9のseed `20260923` は星原7対青凪9・403球・103打席を維持しています。旧v7の犠飛確認にはseed `387276917`（星原3対青凪0、299球）を使えます。旧版の計算・保存はその版で再現します。

v10では内野ゴロの捕球失策による出塁・強制進塁・失策数と、失点／自責点の区別を追加しました。守備回・刺殺・補殺・併殺関与、併殺・野選・犠飛も引き継ぎます。投球・打球・走塁の既存係数は変更していません。失策の仮係数は日本語コメント付きの [config/errors.ts](config/errors.ts)、共通設定は [config/match.ts](config/match.ts) です。編集方法・単位・仮定は [設定の説明](config/README.md) を参照してください。係数の校正は後工程です。

「1イベント進める」は投球のほか、攻守交代や投手交代も1件として進めます。以前の「1球の検証」画面も残してあり、こちらは四球・三振・フェア接触の境界で停止する独立した実験です。

## 対応範囲と仮定

- 架空24選手：各球団は打順9人（DHを含む）と投手3人。球種はストレート・スライダー・フォーク。
- 9回制、同点なら最大12回、裏の省略・サヨナラ・引き分け。先発90球、次の投手50球を目安に打席間で継投します。
- 四死球、三振、単打、二塁打、三塁打、本塁打、打球アウト。能力から打球速度・角度、守備到達時間を計算します。
- 安打時の既存走者は獲得塁数に加え、v2以降では走力・返球時間に応じて最大1塁追加進塁します。犠飛・併殺・野選以外のアウトでは塁上の走者を動かしません。責任投手を走者ごとに保持します。
- v7の併殺：無死・一死で一塁走者がいるP/3B/SS/2Bのゴロ捕球から、二塁フォースと一塁アウトが間に合う場合。打席結果は打球アウトとし、2件のアウトと併殺打を記録します。
- v7の犠飛：無死・一死の外野フライ捕球後、三塁走者が安全余裕を持って本塁へ到達できる場合。打席1・打数0・犠飛1・打点1、走者の責任投手へ失点を付けます。両プレーともその他の走者は元の塁に留めます。
- v8の野選：併殺候補のゴロで二塁フォースだけが間に合う場合、走者をアウトにして打者が一塁へ出ます。打席1・打数1・野選1を加え、安打と併殺打は加えません。入れ替わった打者走者へ元の走者の失点責任を引き継ぎます。その他の走者は元の塁に留めます。
- 送球失策・飛球の落球・盗塁・犠打・振り逃げ・暴投・捕逸・野手交代・二刀流運用・投手の勝敗／セーブは未対応です。疲労・天候・成長も未適用です。三塁・本塁への送球選択、誰もアウトにならない野選、走塁死・飛球併殺、守備率・高度守備指標も未対応です。
- v9の守備：投球時の9人を記録し、守備回・刺殺・補殺・併殺関与を位置別に集計します。三振は捕手の刺殺、直接捕球は捕球者の刺殺、ゴロ送球は送球者の補殺と受け手の刺殺です。一塁手のゴロは自ら一塁を踏む限定仮定。DHと未登板投手の守備成績は作りません。
- v10の捕球失策：P/C/1B/2B/3B/SSの内野ゴロで、通常なら打者だけが一塁アウトになる候補が対象です。成功する併殺・野選は除外します。打者は一塁へ出塁し、押し出される走者だけ1塁進みます。打席・打数・失策を各1とし、安打・打点・アウトは加えません。
- v10の自責点：失策がなかった場合の走者・アウトを回ごとに再構成します。投手ごとは登板時の実際の塁・アウトから別に追跡し、チーム自責点と区別します。後続プレーを調べるため試合終了時に確定します。全規則を扱う公式記録員の判断を実装したものではありません。
- 計算上限は1打席100球・1試合10000球。上限到達は異常停止として扱い、正常な結果として保存しません。

守備回はその選手がその位置についている間のチームのアウト数から表示します。刺殺数とは別です。初期seedのv10は9回裏一死でサヨナラとなり、守備刺殺の合計は星原25・青凪27です。旧v1〜v8の画面には守備成績が未対応であることを表示します。

打率は安打÷打数、防御率は27×自責点÷投球アウトから表示します。投球回の小数部分はアウト数です（5.2＝5回2/3）。未観測の率は「-」、投球アウト0で自責点が正なら「上限」と表示し、非有限数は保存しません。

モデルの仮定は [設定の説明](config/README.md) とローカルの [試作モデル](Docs/knowledge/prototype-model.md) に記録しています。新モデルの計算は `pitch-configured.ts`、`batted-ball-configured.ts`、`in-play.ts`・`in-play-v2.ts`、守備記録は`fielding.ts`、モデル選択は `src/game/model-registry.ts` です。旧v1〜v9の定義と計算は保持します。**実装版は0.14.0（ゲームv1.0の開発途中）**、v10は共通の試合計算アルゴリズムの版です。

## 選手・持ち球・編成の編集

編集場所を `src/data/` にまとめました。値は各ファイルに直接記載し、選手の並び順から能力を生成しません。

| 編集対象                           | 場所                                                           |
| ---------------------------------- | -------------------------------------------------------------- |
| 選手名・左右・打撃・走塁・守備能力 | [players](src/data/players/away.ts) のaway.ts／home.ts         |
| 持ち球・球速・制球・再現性         | [repertoires](src/data/repertoires/away.ts) のaway.ts／home.ts |
| 球団名・打順・守備位置・継投順     | [teams](src/data/teams/away.ts) のaway.ts／home.ts             |
| 球種のコード・日本語名             | [pitch-types/index.ts](src/data/pitch-types/index.ts)          |

編集後は `npm.cmd run data:check` で検査し、再読み込みして新しいv10試合を準備します。v10の過去保存は保存時の名簿で再現・表示します。追加投手・選手入替・既存3球種の持ち球追加に対応しています。新しい種類の球種には計算モデル側の対応も必要です。単位、追加手順、保存互換性は [データ編集ガイド](src/data/README.md) を参照してください。

## v0.1の終了試合保存

IndexedDB＋DexieをStorageAdapter経由で使用します。保存形式はv1の **v01-completed-game-1**、v2の **v01-completed-game-2**、v3の **v01-completed-game-3**、v4の **v01-completed-game-4**、v5の **v01-completed-game-5**、v6の **v01-completed-game-6**、v7の **v01-completed-game-7**、v8の **v01-completed-game-8**、v9の **v01-completed-game-9**、v10の **v01-completed-game-10** に対応し、対象は正常終了した1試合です。v1〜v9は従来の固定名簿、v10は検査を通った編集名簿にも対応します。保存された名簿で再実行し、画面もその名簿を表示します。

v7以降は開始時の設定全体も保存します。v10は捕球能力を加えた架空名簿game-fixture-v2、失策設定、回・投手別の自責点再構成履歴も保存します。設定ファイルを変更しても、保存済みの試合は当時の設定で復元・再実行します。設定内容は定義ブロックのハッシュで識別し、アルゴリズム版と区別します。

4物理ストア（local_worlds、save_slots、save_snapshots、save_blocks）に、モデル定義・名簿・全イベント・最終状態・成績・完全な乱数状態を保存します。版・ハッシュ・再計算による整合確認を通してから復元します。未知の版や破損を検出した場合はエラーにし、表示中の試合を維持します。保存中の失敗では4ストアをまとめて取り消し、以前の保存を残します。

手動保存1枠と直前の保存に対応します。試合中保存・自動保存・外部ファイルへの書き出し・クラウド同期・正式な全世界セーブとの互換性はありません。履歴の自動削除は未実装で、保存を重ねると容量を使います。保存先は同じブラウザ・同じURLのオリジンです。開発用5173番とプレビュー用4173番は別の保存先になり、サイトデータを削除すると保存も消えます。

## 検証

完成判定をまとめて再実行するには、`npm.cmd run verify:v02` を使います。型・計算と保存の試験・ビルド・実ブラウザ試験・書式検査の順に実行し、失敗時はそこで停止します。個別に確認する場合は次のコマンドを使えます。

```powershell
npm.cmd run check
npm.cmd run test:ui
npm.cmd run format:check
```

`check` は型検査・日次進行を含むNode試験・ビルドを行います。試合100条件、走者と得点の境界、継投、サヨナラ、結果確定の二重適用防止、保存失敗・競合・破損拒否を含みます。三塁打は固定名簿の100条件での観測とは分け、極端な能力の分岐試験で確認しています。既存の1球試験は2,000乱数条件を含みます。変更前に凍結したv1〜v10セーブと計40条件の全記録ハッシュで互換性を検証し、実ブラウザでも旧v1〜v9保存→v10保存→前保存の復元を確認します。

新プレーの固定入力試験と80条件の生成試験で、第三アウトでの得点抑止・サヨナラ・責任投手・打席内訳を検査します。野選は別の100条件と固定入力で、一塁・二塁の同時到達、満塁、連続継投での失点責任引き継ぎ、成績・保存記録を検査します。守備記録は別の100条件でv8との全状態・乱数・既存記録の同値性を確認し、刺殺合計＝投球アウト、守備アウト合計＝9×投球アウト、継投・アウト0の出場・改変拒否も検査します。設定の不正値拒否、既定値変更後の保存復元、既定設定での旧v6投球・打球一致も確認します。

捕球失策は固定状況と100seedで得点・自責点・失策・守備アウトの整合を検査します。満塁、仮想第三アウト、失策で早く生還した走者の後続安打、継投による個人／チーム自責点の違い、野選での走者交代、確定処理失敗時の非破壊性、設定・再構成履歴の改変拒否を含みます。失策確率0の20seedではv9のプレーと乱数が一致します。

年間の途中保存・再開と年度末バックアップを単独で確認する場合は、`npm.cmd run test:season`を使います。長時間試験の範囲・記録・未検証項目は[年間プレイの受入検証](SEASON-ACCEPTANCE.md)を参照してください。

`test:ui` はビルド済みのdistを4173番で配信し、インストール済みMicrosoft Edgeでv0.1・v0.2の試験を実行します。1280px・390px幅で、自動進行→保存→ページ再読み込み→復元→前保存→同条件再現と、以前の1球画面を確認します。一時停止・画面切替・再開の結果一致と、破損保存を拒否した後の表示保持・前保存復旧も検証します。Android実機や他ブラウザでの検証は未実施です。

| コマンド                        | 用途                              |
| ------------------------------- | --------------------------------- |
| `npm.cmd run game -- 20260923`  | 画面を使わず1試合の結果をJSON表示 |
| `npm.cmd run pitch -- 20260923` | 以前の1球試作の結果をJSON表示     |

## 構成と開発方針

| 場所                 | 役割                                                     |
| -------------------- | -------------------------------------------------------- |
| `config/`            | 新規v7〜v10試合の係数と編集方法                          |
| `src/data/`          | 選手・持ち球・編成・球種辞書とデータ編集ガイド           |
| `src/engine/`        | 既存の1球計算、乱数、境界検査                            |
| `src/game/`          | 打球・守備・走者、試合進行、成績、指示処理               |
| `src/game-worker.ts` | 試合状態を所有し、指示を直列に処理                       |
| `src/storage/`       | 保存の入口、直列化と検査、Dexie実装                      |
| `src/ui/`            | Reactの画面、表示用コピー、入力                          |
| `tests/`・`e2e/`     | 計算・保存・実ブラウザの検証                             |
| `Docs/knowledge/`    | quiz_app方式の現状・判断・知見・作業履歴（ローカル専用） |

計算はReact・DOM・DBから独立し、Workerだけが試合の正本を更新します。表示、一時停止、保存操作は試合用乱数を進めません。率の表示からカウンタを書き戻しません。試合終了で日付やシーズンを進める処理もありません。

型はデータ設計書v1.0のID・単位・記録境界を参考にした**v0.1試作向けの部分実装**です。正式な全プロフィール・全能力・全世界モデルを実装したものではなく、省略項目を0や空オブジェクトで補いません。

接続先は [5jfv9b7s/BaseballSim](https://github.com/5jfv9b7s/BaseballSim)、**今回以降の開発作業はdevelop**で行います。ユーザーの指定によりAGENTS.mdとDocs/全体はGit除外を維持しています。原資料・知識庫は別PCへ別途引き継いでください。承認済み仕様と試作判断の区別は[判断記録](Docs/knowledge/decisions.md)、次作業は[現状](Docs/knowledge/current-state.md)を参照してください。

依存版はpackage.json・package-lock.jsonで固定しています。今回Dexie 4.4.6と、保存試験用fake-indexeddb 6.2.5を追加しました。通常の計算・保存に常駐Node.js／PostgreSQLサーバーは不要です。書式はPrettier＋EditorConfigで2スペース・幅100文字を目安に揃え、Docs/・AGENTS.md・生成物は自動整形しません。
