# 試作モデルの設定

ゲームv0.1の**新規v7〜v9試合**は [match.ts](match.ts) を読み込みます。既存係数はv6と同値です。実在統計への校正は行っていません。

## 編集と確認

編集用設定は、日本語コメントが使えるTypeScript形式です。ファイル内を「配球」「狙い」「制球」「打者判断」「打球」「守備」「走塁」「併殺・犠飛」の順に整理しています。各値のすぐ上に意味と単位を記載しているため、通常の調整では説明書を往復せず数値を編集できます。

1. 終了した試合を保存してから `config/match.ts` の数値を編集します。項目名や階層は変更しません。`//`から始まる行は説明コメントで、試合計算や保存データには入りません。
2. `npm.cmd run check` を実行します。不足項目・未知項目・非有限数・範囲外・上下限の逆転を拒否します。
3. 開発画面を再読み込みし、「守備成績対応試作 v9」を選び「新しい試合を準備」で適用します。配信済みのdistへ反映するには再ビルドが必要です。開発中のファイル変更で画面が再起動することがあるため、未保存の試合を残したまま変更しないでください。
4. `npm.cmd run game -- 20260923 game-prototype-v9` でも確認できます。

同じseedでも設定が異なれば結果が変わります。開始時に設定全体を複製し、終了試合と定義ブロックへ保存します。保存読み込みは現在のファイルではなく、保存された設定を使用します。設定の識別には定義ブロックのSHA-256を使います。旧v1〜v6は従来の固定定義を使用し、このファイルの影響を受けません。

`game-prototype-v7`〜`game-prototype-v9` はアルゴリズム版、`match-config-v1` は設定構造の版です。**係数だけの変更は保存される設定内容で識別**します。式・分岐・設定項目・許容範囲を変える場合は新しい版を追加し、旧版の再実行を維持してください。固定の検査範囲は [config-schema.ts](../src/game/config-schema.ts)、各範囲は `min`（下限）・`max`（上限）、配列は `items`（要素の範囲）・`length`（要素数）で表し、日本語コメントを付けています。通常の係数調整ではスキーマを変更せず、`match.ts`を編集してください。項目間の条件は [config.ts](../src/game/config.ts) です。検査範囲は数値破綻防止の制約で、校正済みの推奨範囲ではありません。

## 併殺・野選・犠飛の試作式

捕球時間・地点を打球生成時に保存します。時刻は打球接触を0とする整数ms。判定の追加乱数は使いません。

- **併殺**：無死・一死、一塁走者あり、P/3B/SS/2Bが捕ったゴロが対象。2Bが捕ればSS、それ以外は2Bが二塁をカバーし、一塁手へ転送します。塁カバーは投球中から始める仮定とし、準備時間＝投球距離÷実球速×coverPreparationPitchFractionを守備反応＋加速移動時間から差し引きます。負にはしません。二塁到達＝max(捕球＋持替え＋送球距離÷肩速度、カバー到達)、一塁到達＝max(二塁到達＋転送＋塁間送球、一塁カバー到達)。一塁走者は反応＋(塁間−リード)÷走速度。両塁で走者より早く守備が到達する場合だけ、二塁フォース→打者一塁アウトを採用します。同時なら併殺を選びません。旧v7は成立しなければ従来の打者一塁アウトです。v8は次の野選分岐を使います。
- **野選（v8）**：併殺候補のうち、二塁フォースは間に合うが一塁への転送が打者より遅い、または同時の場合です。一塁走者を二塁でアウトにし、打者は新しい走者IDで一塁に残します。二塁でも間に合わない場合は、従来の打者一塁アウトです。この限定的な選択は試作の仮定で、全送球先を比較する判断モデルではありません。投球・打球・走塁・送球の係数と時間式はv7から変更していません。
- **犠飛**：無死・一死、三塁走者あり、LF/CF/RFが捕ったflyが対象。走者は帰塁して捕球を待つ仮定です。走者到達＝捕球＋タッチアップ反応＋塁間÷走速度、返球到達＝捕球＋持替え＋捕球地点から本塁までの距離÷肩速度。走者到達＋安全余裕が返球より早い場合だけ生還します。2アウトからの捕球は得点を生みません。
- 成立判定だけでなく参加選手・役割・比較時刻・準備時間を版付きで保存します。アウト・走者移動の順を保持し、併殺は打数1・併殺打1・投手アウト2、犠飛は打席1・打数0・犠飛1・打点1です。得点は走者の責任投手へ帰属します。
- 野選は打席1・打数1・野選1・投手アウト1、安打0・併殺打0です。アウトはそのプレーの投手に記録しますが、入れ替わった打者走者の失点責任は元の一塁走者の責任投手を引き継ぎます。[公式記録規則9.16(g)](https://mktg.mlbstatic.com/mlb/official-information/2025-official-baseball-rules.pdf#page=147)の走者交代の扱いを参照しています。全守備・失策・自責点規則の完全実装ではありません。
- その他の走者は元の塁に留めます。三塁・本塁への送球選択、誰もアウトにならない野選・走塁死・中継やタッチの細分化・飛球併殺・ライナー/ポップの犠飛・犠飛失策・失策・守備率・高度守備指標は未対応（v9の基本守備成績は下記）です。

これは実装した限定範囲と仮定の説明で、最終仕様の承認ではありません。資料の結果コードと成績項目を継承し、打席結果に独自のdoublePlayを追加せず、battedOutと2アウト・groundedIntoDoublePlaysで表しています。

確認用のseedと画面試験の期待値は同梱設定に対するものです。設定変更後は結果が変わるため、画面試験の新規v7〜v9の期待値は変更内容に応じて確認してください。旧版保存の期待値は再生成しません。計算の基準試験はtests/fixtures/match-v7-baseline.jsonを使用します。

野選の確認はv8・seed `20260923` です。同梱設定では野選1件、青凪のplayer-h-03は打席5・打数5・安打2・野選1です。v8の成績定義はgame-stats-prototype-v3で、旧版に未対応の野選カウンタを追加しません（画面は「–」）。

## v9の守備記録と集計

v9は試合結果・投球/打球/走塁の時間式・乱数・係数をv8から変更しません。新しい確率や係数はありません。設定値はv7〜v9共通で、保存時に各試合の開始時設定を固定します。

投球時の守備9人（DH除外・登板中の投手）と、成立したアウトへつながる捕球/送球/受球/刺殺を保存します。投手交代後は次の投球から新しい投手へ守備アウトを付けます。アウトを取れず降板した投手も、投球に参加していれば出場1・守備アウト0を記録します。未登板者の行は作りません。

| プレー                         | 刺殺                 | 補殺・併殺関与                                            |
| ------------------------------ | -------------------- | --------------------------------------------------------- |
| 三振                           | 捕手1                | 投手への補殺なし。振り逃げは未対応                        |
| fly/line/popupの直接捕球・犠飛 | 捕球者1              | 補殺なし                                                  |
| 通常のゴロ送球                 | 一塁手1              | 送球者1                                                   |
| 一塁手のゴロ処理               | 一塁手1              | 自分で一塁を踏む仮定、補殺なし                            |
| 二塁フォース→一塁併殺          | 二塁カバー1・一塁手1 | 捕球送球者と転送者へ補殺各1、3人へ併殺関与各1             |
| 併殺崩れの野選                 | 二塁カバー1          | 二塁への送球者だけ補殺1、転送失敗に補殺なし・併殺関与なし |

刺殺・補殺・併殺関与の記録根拠は[公式記録規則9.09〜9.11](https://mktg.mlbstatic.com/mlb/official-information/2025-official-baseball-rules.pdf#page=135)を参照しています。一塁手の自己処理、三振捕球、対象プレーの限定は試作仮定で、全規則・全守備判断の実装ではありません。

守備回はfieldingOutsを3で割った回と余りのアウトで表示します。各位置の出場中にチームが取ったアウトを数え、刺殺と区別します。失策と守備率は未実装なので0や1.000を補いません。守備交代/位置変更、投手の一塁カバー、安打回収・犠飛返球などアウトに結び付かない全動作、中継・タッチ・失策判定・高度指標も未対応です。defensive_stintsの完全実装ではなく、投球時の配置から現在の範囲を再構成します。

保存形式9・成績定義game-stats-prototype-v4。旧v1〜v8は元の計算と保存を保持し、未対応の守備行を追加しません。
