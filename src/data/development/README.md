# 現行120人の追加能力・適性（0.36.0）

通常プレイの架空4球団120人について、追加11能力、9位置の適性と習熟、先発/救援適性、才能/向上心を保存する入力です。**提供資料の候補70人とは別データです。** 実在選手の査定ではなく、動作確認用の未校正の固定例です。

## 編集先

`hoshihara/`・`aonagi/`・`kohaku/`・`asagiri/`へ各30人を、一人1 JSONで分けています。ファイル名と`playerId`は同じ固定IDを使います。改名や並べ替えでIDを変えません。[index.ts](index.ts)へ固定IDとJSONを明示的に登録します。

| 入力                                | 内容・制約                                                                                    |
| ----------------------------------- | --------------------------------------------------------------------------------------------- |
| `additionalAbilities`               | バント、盗塁、走塁、スローイング、ポジショニング、捕手3能力、怪我耐性、クイック、牽制の11能力 |
| 能力の`valueMilli` / `ceilingMilli` | 整数、0 ≤ 現在値 ≤ 個別上限 ≤ 120000。表示値の1000倍                                          |
| `positionSkills`                    | P/C/1B/2B/3B/SS/LF/CF/RFの9位置。DHは含めない                                                 |
| `aptitudeMilli`                     | 固定の向きやすさ、0〜120000。成長上限は追加しない                                             |
| `familiarity`                       | 習熟の現在値と個別上限。適性と独立して指定できる                                              |
| `pitchingAptitudes`                 | 先発・救援の固定適性、0〜120000。0を登板禁止として扱わない                                    |
| `growthProfile`                     | 才能・向上心、0〜120000。それ自体に成長上限を追加しない                                       |

既存11能力は従来の入力を正本にします。ミート・パワー・選球眼・走力・守備範囲・捕球・肩力は[../players/](../players/)および[../farm/](../farm/)、スタミナ・回復は[../physical/](../physical/)で編集します。ここへ既存能力を重ねて保存すると検査エラーになります。

22能力は読み取り時に結合します。[共通辞書](../../players/abilities.ts)、[型](../../world/player-development-types.ts)、[結合・検査](../../world/player-development.ts)を参照してください。全選手に22能力を用意し、普段使わない分野を欠測や0で一括代用しません。実際の能力0は有効な入力です。

## 新規プレイと旧保存

22能力を追加した定義v19の入口は[../world/player-development.ts](../world/player-development.ts)です。現行の新規プレイは[../world/training-plans.ts](../world/training-plans.ts)の定義v20でこのデータを継承します。開始時に全入力を複製し、保存・バックアップにも含めます。編集は新しく作るプレイへ反映します。既存セーブを現在のJSONで更新する処理ではありません。

定義v19の新規保存は0.35.0以前のアプリでは未対応です。旧定義v18以前へ追加値を後付けしません。旧保存の選手詳細は、当時記録された能力だけを表示し、追加能力・適性は「記録なし」とします。`createTwoLeagueDefinitions`など旧版の入口は保持しています。

## 架空初期値と未接続

新しい11能力は、投手/捕手/その他の固定例へ0〜8ポイントの差を付けた初期値です。個別上限は110。守備は代表位置を適性80・習熟70、同系統を55・40、それ以外を30・20の初期例とし、同じ小差を付けています。習熟上限110は適性から導出していません。先発/救援は投手80/70・その他20/20を初期例としています。才能50〜58、向上心55〜67です。

この作成規則は今回の固定JSONを用意したときの仮定です。実行時に代表位置や配列順から再生成する式ではありません。プロフィールの代表位置を変更しても、記録済みの適性や習熟をリセットしません。実在資料から推定した値、成長曲線、最終的な能力分布とは区別してください。

**追加11能力、適性・習熟、才能・向上心は表示・保存のみです。** 現行v11の試合計算にはまだ接続していません。選手詳細の「未接続」表示が対象を示します。既存11能力の計算と係数は維持し、練習・恒久成長・怪我・新しい技能モデルは後続工程です。提供候補70人の正式投入可否や未決定の資格・代表位置を変更しません。

## 確認

```powershell
npm.cmd run data:check
node --test tests/player-development.test.ts
```

`data:check`は短期・年間で120人の全項目・単位・上限・重複・所属との一致を検査します。「チーム」→選手名で22能力と分野フィルター、「守備適性・習熟（9位置）」で固定適性と習熟、「状態・成長」で才能・向上心を確認します。評価文字は表示整数から求め、内部89.999はA・89、90.000でS・90です。
