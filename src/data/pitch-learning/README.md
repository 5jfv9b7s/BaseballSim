# 新球種習得の候補入力（0.45.0）

`球団名/選手ID.json` を編集し、`index.ts` に登録します。1人に複数候補を追加できます。候補は既存の登板対象投手のみで、初期の習得済み持ち球は `../repertoires/individual/` に残します。`npm.cmd run data:check` で新規の短期・年間定義を検査します。

各候補には不変の `pitchId`、本人の `playerId`、対応済みの `pitchTypeCode`、習得進度、制球・再現性と上限、球速、回転・リリースを明記します。進度の100000が100%、99999は未習得です。候補追加では他の持ち球とIDを重複させないでください。試合モデルに未対応のコードは使えません。

現行24投手へ1球ずつ設定した架空の検証入力です。初期候補は未所有のカーブ→チェンジアップ→カッター→シンカー→スプリッターの順から最初の1球を選びました。初期制球・再現性は本人のストレートの70%、球速は球種に応じ80/87/94/93/90%、回転・軸は既存球種テンプレート、リリースは本人の値を基に固定しました。**生成時の仮定であり、毎日計算する式や最終査定ではありません。** JSONの値を個別に編集できます。

進行中の正本は保存内の `growth.state.acquisition`、候補入力は保存内の定義です。設定を編集しても開始済みプレイは変わりません。習得日と進度は別に記録し、習得した翌日以降の試合で使います。制球・再現性は未習得中は固定し、習得後に練習・経験・年齢変化の対象になります。

速度は `config/pitch-learning.ts`、機会・才能・強度・疲労は `config/growth.ts`、キャンプ指定補正は `config/camp.ts` です。いずれも未校正の試作値で、完成日は保証しません。旧保存は旧モデルのままです。
