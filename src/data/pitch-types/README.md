# 球種を追加・調整する

## 初期候補だけの追加4球種（0.34.0）

[initial-2026.ts](initial-2026.ts)は、候補の単球検証専用にツーシーム・シュート・ナックルカーブ・パームを加えた13球種カタログです。追加テンプレートは[候補データ](../initial-2026/README.md)の物理ルールv0.5から取った未校正の仮設定です。各候補持ち球の個人回転・リリースを優先します。配球案は未接続で、指定球種だけを検証します。

下記の通常プレイ用`profiles.ts`は従来の9球種を維持します。追加4球種を通常名簿へ書くだけでは投球できません。正式投入には新しい初期定義と保存互換性の検証が必要です。

開発版0.26.0では、名前・球種の基本特性・投手の持ち球・共通係数を分けています。**数値はすべて未校正の架空データです。** 名前を登録するだけで投球可能にはなりません。

| 編集内容                                     | ファイル                                                                   |
| -------------------------------------------- | -------------------------------------------------------------------------- |
| 球種コードと名前の候補                       | [index.ts](index.ts)                                                       |
| ストレート・カッター・シンカーの特性         | [fastballs.ts](fastballs.ts)                                               |
| スライダー・カーブ・スイーパーの特性         | [breaking.ts](breaking.ts)                                                 |
| フォーク・スプリッター・チェンジアップの特性 | [offspeed.ts](offspeed.ts)                                                 |
| 特性ファイルの組み合わせ                     | [profiles.ts](profiles.ts)                                                 |
| 現行の投手別の全持ち球・個人の球質           | [../repertoires/individual/README.md](../repertoires/individual/README.md) |
| 全球種共通の試作係数                         | [../../../config/pitch-shape.ts](../../../config/pitch-shape.ts)           |
| 1球の計算                                    | [../../engine/pitch-profile.ts](../../engine/pitch-profile.ts)             |
| 回転から変化量への計算                       | [../../engine/pitch-movement.ts](../../engine/pitch-movement.ts)           |

現在の対応は上記9球種です。辞書にある残りの球種は候補のまま保持しています。持ち球に対応する特性がなければ検査エラーとなり、別の球種へ自動置換しません。新規日程は4球団24投手・80持ち球です。すべてに個人別の球質を明示しています。共通テンプレートは省略時の既定値で、個人設定のある球へは適用しません。

## 追加手順

1. `index.ts`に一意のコードと表示名を記入します。保存で識別するコードは改名しません。
2. 分類別の特性ファイルに`PitchProfile`を追加します。`code`は辞書と一致させます。`name: PITCH_TYPES.コード.name`で辞書の表示名を参照し、開始時に名前も保存します。新しい分類ファイルを作った場合は`profiles.ts`から読み込みます。
3. `repertoires/individual/球団名/選手ID.ts`へ持ち球を追加します。`pitchId`は全体で一意、`playerId`は所有する実在の架空選手ID、`pitchTypeCode`は上で登録したコードにします。球速・制球・再現性はこの持ち球に記入します。習得進度100000の持ち球だけが投球対象です。
4. `npm.cmd run data:check`と`npm.cmd run check`を実行します。
5. 開発画面を再読み込みし、新しいプレイを準備します。開始済みのプレイや旧セーブへ編集内容は反映しません。本番ビルドでは再ビルドも必要です。

通常の特性追加には`pitch-configured.ts`を変更しません。v1〜v10の試合は旧3球種と従来の式を再実行します。新しい種類の運動（例：ナックルの不規則な軌道）を実装する際は、新たな計算モデル版と検証が必要です。

## 特性の入力

| 項目                           | 意味・単位・検査範囲                                                           |
| ------------------------------ | ------------------------------------------------------------------------------ |
| `selection.baseWeight`         | 基本の配球重み。0より大きく100以下                                             |
| `selection.twoStrike`          | 2ストライク時に基本重みへ掛ける倍率。同範囲                                    |
| `selection.threeBall`          | 3ボール時の倍率。同範囲                                                        |
| `selection.oppositeSide`       | 投手と打者が異なる左右のときの倍率。同範囲                                     |
| `delivery.spinRateRpm`         | 基本回転数。整数0〜5000 rpm                                                    |
| `delivery.spinSpreadRpm`       | 回転数の片側のばらつき。整数0〜1000 rpm、基本回転数以下                        |
| `delivery.spinAxis`            | 右投手の回転軸。単位ベクトルを1000000倍した整数3成分。長さの誤差は0.000002以下 |
| `delivery.release.lateralMm`   | 右投手のリリース左右。−1500〜1500 mm                                           |
| `delivery.release.heightMm`    | リリース高さ。500〜3000 mm                                                     |
| `delivery.release.extensionMm` | リリースの前方距離。0〜3000 mm                                                 |

捕手視点でxは右、yは投手方向、zは上です。左投手は回転軸zとリリース左右を反転します。回転軸は角度（度）ではありません。基本設定は名前で表す球種の架空テンプレートで、実在球種の代表的な測定値を保証しません。

投手固有の値を使う場合は持ち球へ`delivery`を丸ごと指定します。エンジンは省略時に球種のテンプレートを使い、部分的な上書きはしません。0.26.0の新規入力データは全持ち球の個人設定を必須として検査します。新規プレイの球質を変える場合は選手ファイルを編集してください。共通テンプレートだけを変えても、個人設定のある球の回転・リリースは変わりません。

```ts
delivery: {
  spinRateRpm: 2100,
  spinSpreadRpm: 150,
  spinAxis: { xPpm: -800000, yPpm: 0, zPpm: 600000 },
  release: { lateralMm: -430, heightMm: 1750, extensionMm: 1650 },
},
```

## 試作の計算と限界

`game-prototype-v11` / `pitch-prototype-v6` / `pitch-shape-v1`で採用する仮定です。データ設計書v1.0の5.4にある、制球と再現性の分離、実単位、変化量の導出、過去記録の固定に対応する第一段階です。正式な物理モデルではありません。

配球重みは基本重み×該当するカウント倍率×左右倍率です。規格化して乱数で1球を選びます。制球による到達位置誤差と球速の式は、従来の`config/match.ts`を使います。v11の配球重みは特性ファイルを参照し、`match.ts`の旧3球種の重みを使いません。

```text
r = 再現性 / 120000
回転幅 = spinSpreadRpm × (1 − r)
回転数 = round(spinRateRpm + (2u − 1) × 回転幅)

S = 回転数 × breakMmPerRpm × (基準球速 / 実際の球速)^2
横変化mm = round(S × 回転軸z / 1000000)
縦変化mm = round(−S × 回転軸x / 1000000)
```

`u`は保存可能な乱数生成器の0以上1未満の値です。回転数用の抽選は球速の直後に1回だけ追加します。負のゼロは0へ正規化します。変化量は**同じ基準条件の無回転球との差**です。縦が正でも実際の球が上昇する意味ではなく、シンカーやフォークも正になり得ます。

狙いはホーム付近の到達目標です。平均の変化を織り込んだ投球と仮定し、最終位置へ加えるのは「実際の回転による変化−基本回転による変化」です。同じ位置誤差へ再現性を二重に適用しません。

```text
d = 選球眼 / 120000
読み残す割合 = 1 − recognitionBase − recognitionDiscipline × d
打者が予測する位置 = 実際の到達位置 − 変化量 × 読み残す割合
接触率 = 従来の接触率 − 予測誤差の長さ(m) × contactPenaltyPerMeter
```

認識係数の合計は1以下です。振るかどうかには予測位置、見逃し判定には実際の位置を使います。接触率は従来の上下限へ収めます。選球眼から変化の認識を推定する部分も仮定です。コントロール・回転・接触の各係数は統計で校正していません。

この段階では定加速度に相当する到達点の近似だけを行います。重力・抗力を含む3次元の連続軌道、回転軸・リリースのばらつき、ナックルの不規則変化、球種習得・成長は未実装です。リリースは入力を記録するだけで計算へ使わず、未実装の影響を係数に混ぜません。`measurement`は計算上の出力で、実測値を意味しません。

## 保存と確認

球種名・特性・持ち球・共通係数は開始時に複製し、保存へ含めます。読み込み後は保存内の入力を使い、今の設定で過去の投球を上書きしません。旧投球の未算出の回転や変化量は`null`のままです。

新規世界は`world-prototype-v15`、初期定義は`world-definitions-v15`（0.25.0はv14）、内部保存形式は`v016-world-snapshot-v15`です。旧世界は読み込み時に自動変換しません。新しい初期定義の保存は0.26.0以降で開いてください。データ内容の更新なので、世界・試合・測定モデルと保存形式は0.25.0と同じです。

画面では新規プレイの「チーム」→投手名→「球種の特性（試作）」を開きます。基本回転・通常球速からの目安が表示されます。実際の1球は`/?tools=1`の「球種特性対応試作 v11」で確認できます。コンソールでの試合は`npm.cmd run game -- 99 game-prototype-v11`です。

プログラムから新規試合を作る場合は`createGame(seed, undefined, 'game-prototype-v11')`を指定します。引数を省略した従来の`createGame()`は互換性のためv10を維持し、UI・CLIは現行版を明示します。

検証の入口は[球種のテスト](../../../tests/pitch-profiles.test.ts)と[画面テスト](../../../e2e/pitch-profiles.spec.ts)です。旧世界v14の比較用記録は導入前コミット464a85fから作成しており、現行計算で期待値を更新しません。
