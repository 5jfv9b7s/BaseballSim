## 0.53.0：給与債務の組替えと両球団の予算審査

[payroll.ts](payroll.ts)で契約年度・負担期間・期日を記録した給与債務を作成し、移籍時の未払分を組み替えます。[trade-finance.ts](../recruitment/trade-finance.ts)は、複数選手の現在・将来の給与と提示金銭を一つの会計案へまとめます。型は[trade-finance-types.ts](../recruitment/trade-finance-types.ts)へ分けています。

### 給与を二重計上しない

- 旧給与債務は`reallocated`で残し、支払済み額・元の期日・発生元・過去の現金明細を消しません。
- 置換先は未払額だけを新規債務にします。旧債務に残した既払額を置換先へ再び既払として写しません。
- 各契約年度で、**全履歴の既払額＋現在有効な未払額＝契約年額**を組替え前後に検査します。
- 元債務IDと置換先ID・既払・旧球団の残る未払・移す未払の対応を返します。取引履歴と一緒に保存する接続は今後の工程です。
- 再移籍時のIDへ前のIDを再帰的に埋め込まず、取引・契約年度・選手・期間から作ります。配列順や氏名をIDにしません。
- 契約が明示的に0円なら0円の負担期間を記録します。契約・期間の未記録を0円として補いません。

例：試験専用の10日間・年額100円で、5日目終了までの旧球団負担が50円、既払20円の場合、旧債務の既払20円を残し、旧球団の未払30円と新球団の未払50円を作ります。実際のゲーム初期給与ではありません。この確認例のテスト実行は保留しています。

有効日から獲得側負担、元の支払期日を継承する境界は、**組替え試作`salary-transfer-v1`**です。日割りの式は従来の`salary-day-proration-v1`を使います。旧球団の既払が移籍前負担を超える前払いは、返金・相殺の規則を勝手に決めず`unsupportedPrepayment`で止めます。給与以外の未払契約金等がある場合も、負担規則未対応として`unsupportedContractDebt`で止めます。最終仕様の承認とは区別します。

### 両球団を一つの案で審査する

1. 正本の台帳は一つだけ受け取り、球団別には確定残高・仮確保・将来の保証収入等を受け取ります。
2. 全選手の給与を組み替え、正の提示金銭があれば同額の支出・収入と決済済み債務を同じ案に作ります。金銭0の選手交換では明細を足しません。
3. その全案から両球団の成立後予算を計算します。現在の未払だけでなく、将来の給与不足予約も新球団側へ反映します。
4. どちらかの予算が不明・不足なら`blocked`で理由を返し、適用用の`ledger`を返しません。給与の二人目で止まった場合も、それ以前の選手だけを適用する案は返しません。
5. 両球団の成立後予算が既知で非負の場合だけ、`trade-finance-plan-v1`の`ready`と全会計案を返します。成立前の不足が放出で解消する場合は、成立前だけを理由に拒否しません。

提示金銭は現金に一度だけ反映し、決済済み債務を再び未払として控除しません。残高確定時点以後のイベント順を要求し、未来の現金明細を利用する入力は拒否します。移籍選手の未来の給与年度を省いた入力、同じ取引の反映済み会計記録、不正な所属方向・重複選手も検出します。

**`ready`は会計案だけの審査通過です。** 交渉承認、現在の所属確認、支配下・登録・編成・投手運用・個別設定、保存の一括確定は未接続です。この結果だけでUIの交渉成立を有効化していません。初期契約・資金を捏造せず、既存世界・保存を移行しません。

## 契約と給与期間

`createContractYears`には開始年度・年数・総年俸・契約金と、**順序付きの年度ID／給与適用期間**を渡します。年度IDから西暦を推測しません。総年俸を整数で均等分割し、円の端数は最終年へ加えます。契約金は年俸へ混ぜません。保証の有無も明示します。

既存契約の給与負担期間は資料の2月1日〜11月30日です。内部の期間は`[開始日, 終了日)`なので、既定の終了日は12月1日です。[config/finance.ts](../../config/finance.ts)へ分離しています。**新規の途中加入契約へこの期間を自動流用しません。**

日割りの端数の置き方は、今回の**試作`salary-day-proration-v1`**です。最終仕様の承認とは区別します。期間開始からの日数を使い、以下の累積額の差を各球団へ配分します。

```text
累積額(日) = floor(契約年額 × 期間開始からの日数 ÷ 給与負担期間の日数)
区間の負担額 = 累積額(区間終了日) − 累積額(区間開始日)
```

うるう日は実際の日数に含めます。全区間が重複・空白なく全期間を覆うことを要求し、総額が契約年額と一致するようにします。途中で再分割しても、変更前の区間の金額を変えません。期間・負担球団は入力が必要で、推測で補いません。計算中はBigIntを使い、保存候補は安全な整数のnumberへ戻します。

`allocateSalaryYear`は配分だけを担当します。0.53.0の`reallocateSalary`が既払を保持する未払の再割当を追加し、実際の支払は`recordPayment`が担当します。前払い調整と世界・保存への一括接続は未対応です。

## 予算

```text
現金 = 確定残高 + その確定時点より後の入出金
将来不足予約 = 年度ごとの max(0, 保証未払債務 + 最低編成補充余裕 − 今後の保証基礎収入) の合計
利用可能額 = 現金 − 当季未払 − activeの仮確保 − 将来不足予約
```

- 確定時点はゲーム内日付とイベント順です。同日の確定以前の明細を再計上しません。
- `null`は未記録・未取得、`[]`は取得済みで対象なしです。一部だけ取得した台帳は渡せません。記録済みの0円はそのまま0円として扱います。
- 対象年度にない未払・有効な仮確保、未記録の保証収入・補充余裕があれば`unknown`と理由を返します。
- `waived`・`reallocated`の旧債務と、`replaced`・`released`の仮確保を再控除しません。仮確保の置換先債務の存在を検査します。
- マイナスの利用可能額は不足としてそのまま返します。0へ切り上げたり、借入や追加資金で補ったりしません。
- 初期資金・保証収入・補充余裕の値／決め方はE-01の未決定事項です。今回のconfigには架空の初期金額や係数を入れていません。
- 月別収益の発生・シーズンオフ入金・基礎収入の作成と精算は未実装です。

## 支払と所属計画の境界

`recordPayment`は既存債務を対象に、未払額の範囲内の支払と現金明細を同じ戻り値へまとめます。球団間の支払は同じ精算グループに同額の支出・収入を作り、選手宛て給与には架空の相手球団入金を作りません。新たな債務や現金を無断で発生させません。

発生元は文字列配列の構造化キーです。分割支払では精算番号を含めます。同じグループ・同じ条件の再送は変更しません。同じグループの条件変更、別グループでの発生元再利用、片側しか残っていない同じ精算は拒否します。

予算審査・交渉承認は`recordPayment`の担当外です。0.53.0の`planTradeFinances`が両球団の予算審査を担当します。所属・登録・起用設定を含む全制約と交渉承認は別途必要です。**会計更新だけをもってトレード成立とは扱えません。**

`planTradeMemberships`は旧球団の履歴を閉じ、選手IDを維持して新球団の履歴を追加します。時点はゲーム内日付とイベント順で比較し、現在所属の重複・取引内の選手重複・移籍元不一致・未知の球団・過去への移籍を拒否します。同じ取引が反映済みなら拒否し、再適用防止は今後のWorker指示の境界で行います。登録・オーダー・投手運用・固定設定・個別練習・試合前名簿・過去成績は変更しません。
